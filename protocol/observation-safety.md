# Publication, developer safety and completed-frame contracts

**Normative contracts, not enabled observations.** [Wire v1](wire-v1.md), [field eligibility](visibility.md) and [developer safety manifest](developer-safety-v1.json) apply together. `shared/Protocol/ObservationSafety.cs` checks **supplied evidence**, not game behavior. A bounded named-read developer sampler now supplies private instantaneous evidence; [installed-source audit](../docs/developer-safety-audit.md) records its finite coverage and limits. Private irreversible safety/readiness/source epochs and conservative callback-boundary sampling now exist; [epoch audit](../docs/observation-epochs.md) defines release/owner interfaces and their limits. A bounded event ring and canonical Message/StandardLetter adapter now feed scheduled `events.read`; [event audit](../docs/public-events.md) records acceptance/availability proofs, finite bounds and unsupported types. Other baseline producers are staged separately; image decoding/native rendering remain unfinished. Pure tests/net472 compilation do not establish Mono behavior.

## Accepted public publication

An event means **new accepted player-facing delivery**, not an invocation, attempted incident, archive scan or internal simulation change. It need not be inside the current camera or have its letter dialog open. Normal public notification availability is the boundary.

| Source outcome | Publish? | Required evidence |
| --- | --- | --- |
| `ReceiveLetter` called with future delay | No | Queued letter is not public; never copy its text, arrival tick or queue position. |
| Letter fails `CanShowInLetterStack` or never enters public stack | No | A successful method return alone proves nothing. |
| Delayed letter later actually accepted into public stack | Once, at delivery | Audited canonical acceptance, public membership and public presentation, not original enqueue. |
| Message rejected as empty/duplicate | No | Duplicate timer reset, flash or sound is not a new publication. Do not call `AcceptsMessage` to test: it can mutate timers. |
| Message accepted into public live messages | Once | Canonical acceptance/public membership; `historical:false` does not mean private, but limits later history availability. |
| Outer overload and inner canonical callback observe same delivery | Once total | One canonical acceptance identity; never independent publication per patched overload. |
| Save/archive restoration, bridge startup or hook attachment | No historical replay | No scanning old letters/archives and calling them new delivery. Lifecycle can report readiness. |
| Supported accepted notification while unsafe/loading or payload unaudited | No | Drop without buffering raw text for later replay. No internal sequence, cursor, count or timing event for the failed projection. |

Adapters must audit final full-profile patch behavior, exact notification type/producer and text path. Base-class membership and `CanShowInLetterStack` alone do not approve arbitrary custom getters. Prove accepted public membership without calling game delivery/acceptance methods again. Never cause pause, sound, flashing, archive insertion, `Received`, dismissal, opening, hover, selection or target highlighting. Acceptance caused by normal game is not bridge mutation; repeating acceptance would be.

`PublicEventPolicy.CanPublish` requires `AcceptedPublic`, audited payload, first canonical publication and safe observation. Adapter owns those facts. Dedup is per **acceptance**, not forever by text or raw game object ID: a later genuinely new public message may reuse identical text. Canonical hooking/reentrancy accounting must be bounded; no unbounded seen-object set. If final acceptance cannot be proven, omit route with explicit unverified capability, not guessed events.

### Payload, history and lifecycle

- Notifications contain only `kind:letter|message`, optional audited public `label` (<=512 UTF-16 units), and audited public `text` (<=2,048). Preserve localized Unicode. Materialize approved presentation text once at accepted delivery; do not serialize game objects, invoke arbitrary later getters, expand link targets or truncate a failed audit into a success. Oversized/unaudited records are omitted before retention/sequence allocation.
- No `debugInfo`, look targets, hyperlinks/target handles, quest/faction objects, raw IDs, scheduled delivery times, future incidents, hidden counts or internal sequence. Current v1 notification schema carries **no references**. Any future reference extension needs separate audit plus read-time eligibility revalidation; historical text cannot be used to resolve now-hidden targets.
- Retained text is notification history, not a current-world fact. Retain only while matching normal player availability: archived supported notifications can remain historical; live-only/nonhistorical messages must cease being retrievable when normal live availability ends. Proving that distinction is an adapter obligation, not permission to retain everything indefinitely. Loss of retained availability requires explicit gap/resync rather than silently claiming complete history across removed entries.
- Lifecycle `kind:lifecycle` has **no label** and fixed `text` only: `observation_ready` (initial ready scope), `scope_changed` (new public scope after transition), `observation_resumed` (safe availability restored). No free-form exceptions, debug flags, load internals, hidden simulation reasons, per-hook failures or request diagnostics. Emit only actual public bridge-state transitions, not on every poll/update. No lifecycle payload during unsafe/not-ready period; restore once safe, without replaying notifications missed there.
- Filter before ring insertion, bytes, sequence and cursors. `events.read` never consumes/dismisses game notifications or shared reader state. The wire's 256-entry/262,144-byte ring, 64-item pages, 128 cursor boundaries, five-second cursor lifetime, explicit `event_gap` and scope reset rules still apply. Overflow has no lost-count field. No pre-bridge completeness promise, including first read from oldest retained event.

## Developer refusal

Authenticated `health`/`capabilities` remain minimal bootstrap exceptions, not observation bypasses. Every state-bearing observation, event read and screenshot fails with fixed **`observation_refused`**, without flag/window names or partial data, if any condition holds:

1. `Prefs.DevMode` enabled.
2. Any known developer panel present, even if unfocused, occluded or DevMode subsequently disabled. Manifest includes `LudeonTK.Window_Dev` ancestry, explicit original descendants including corrected `LudeonTK.Dialog_DevPalette`, plus ordinary Window-derived health-edit, pawn-table-test, render-tree and camera-config families. [Audit](../docs/developer-safety-audit.md) lists exact installed types. Known derived panels count too; an exact-name comparison that misses ancestry is insufficient. Read known type membership only; do not evaluate panel internals to classify it.
3. Any explicitly listed static boolean differs from its normal baseline in `developer-safety-v1.json`. This includes lingering `showHiddenPawns`, `showHiddenInfo`, god mode/palette, expanded search/locomotion display, disabled fog or normal render layers, and developer draw/write/show overlays. `drawFog:false` is unsafe, not a false-means-safe exception. Normal-true layers must remain true; normal-false debug surfaces remain false. These audited developer render/inspection flags, including persistent health-card hidden-row/debug-tooltip switches, can survive turning DevMode off. The manifest additionally requires both active developer tool references to be null. Do not depend on a DevMode-gated convenience property such as `ShowDevGizmos`.
4. Required audit cannot finish safely: missing/changed known type or flag, incompatible build, unreadable/budget-exhausted window scan, or incomplete safety sampling. Unknown means refusal, not safe.

Manifest is a **finite explicit read list**, not permission for arbitrary reflection, property enumeration, or sending runtime type names/flag values over wire. Adapter uses audited named static field reads and known type checks on game thread: exactly 185 static reads, at most 64 windows, within the existing shared update deadline. Only the two private health fields need exact metadata binding to cached read delegates; no runtime field enumeration, FieldInfo.GetValue or reflection observation is permitted. Unknown/incomplete evidence never authorizes a producer. Log-only or unrelated developer fields not in manifest are not an implied observation API. Unknown ordinary windows have no structured internals; arbitrary third-party developer screens cannot be recognized/redacted universally. Do not claim otherwise. Newly discovered unsafe surface requires extending audit/manifest before claiming coverage.

Recheck at execution, snapshot/event publication, render start/completion and capture release. Developer refusal takes precedence over not-ready. Never disable flags, close windows, toggle DevMode, force a repaint or edit settings to make observation succeed. If manifest safety conflicts with a mod's nonnormal rendering, refuse and report compatibility limitation outside observation payload; do not silently weaken baseline.

## Completed safe rendered frames

`Root.Update` sampling is **not render completion**. Screenshot success identifies newly completed safe render, not request time, PNG encoding time, simulation tick or a matching JSON frame integer.

1. On safe/ready request admission, record exact scope, private safety epoch and current frame in `CaptureRequestStamp`. No screenshot from a cached earlier frame. Require completed render frame **strictly newer** than request frame; waiting at least next frame avoids releasing an earlier/partially rendered frame from the request's update.
2. Private positive safety epoch identifies one uninterrupted audited safe/readiness interval. Rotate irreversibly on developer/panel/flag transitions, loss or uncertainty of safety/readiness, loading, root/scene/game/map changes, render-target/size/scale invalidation and frame-counter discontinuity. Returning to same flags/scope/frame does not restore old epoch. Detect changes at relevant render/game-thread boundaries, not only network polling; counter wrap must never recycle an epoch. Current private tracker conservatively revokes leases across unobserved update/GUI intervals, audited mutation brackets and invalid/incomplete samples; it does not certify those intervals safe or supply completed-render evidence. Later native provenance must establish that evidence without relabeling revoked epochs.
3. Menu capture requires a **whole safe frame** in that interval, with same scope/epoch throughout render, capture and readback; its full primary-color replacement excludes stale unsafe pixels. **User-approved map-view exception (paused/live):** capture shows what the game displayed under depth-only primary clear, without claiming every primary pixel was replaced. It requires a frame newer than the request, the capture's passed GPU fence, and uninterrupted safety/readiness/scope/size/scale across hold-then-release. `RenderEvidence.MapViewSafe` records this weaker proof separately from `WholeFrameSafe`; render-mode changes revoke it. World/specialist capture remains unverified. `WaitForEndOfFrame`, capture return or nonblack PNG alone proves neither basis. Host evidence is not real-game pixel proof.
4. `CompletedRenderStamp.Complete` checks fresh frame, completion, scene-specific proof (menu whole-frame or approved map-view displayed-frame), current readiness, exact scope and epoch; assigns independent random `c_` identity. `Responses.Capture` requires this stamp. Stamp is not authorization to call Unity from worker or skip later checks. Screenshot stamp never equals separately sampled JSON stamp by design; even equal frame integers do not establish correspondence.
4a. **Hold then release (phase-4 divergence).** The pixels are read privately at the safe capture frame's end and held **unreleased**; the native CPU fence for that capture may pass only on a later frame (observed on the real OpenGLCore/multithreaded renderer). Release requires that later fence pass **and** a fresh game-thread recheck of the same private epoch, root/game scope and render size/scale with no unsafe interval in between (any of those rotates the epoch). Any change, refusal, unwitnessed frame, cancel or the 2-second flight limit discards the bytes. A fence pass alone never releases anything. The reported render frame is the frame whose pixels were read.
5. Encode bounded PNG, release all temporary textures/render resources on success/cancel/error, then recheck `CheckRelease` on game thread immediately before admitting response. If scene/epoch changed, refuse/expire whole result. Current dev state gives `observation_refused`; changed public scope `stale_scope`; lost safety interval/incomplete render `not_ready`; cancellation/deadline never leaves latent capture. Invalidate queued/pending/cached captures on every transition, including dev on then off during encoding.
6. Return only actual image width/height/UI scale, completed render frame, scope, capture ID, `phase:completed_render` and bounded encoded PNG. Private epoch/evidence, native handles, filesystem paths and hidden diagnostics stay absent. CLI decodes once and validates complete PNG/dimensions/length; wire validation is not image decoding. Do not change resolution, UI scale, camera, pointer, selection, overlays or simulation for capture.

One in-flight capture, session-wide cadence and numeric image/frame/byte/deadline budgets remain wire requirements. If current render cannot be captured safely within bounds, return explicit failure rather than partial image. Do not acknowledge complete until image is complete. Final publication boundary authorizes a historical safe image; network delivery is not an atomic promise that game remains unchanged after bytes begin leaving. Already transmitted bytes cannot be recalled; current unsafe frames must never be admitted; unlike menu capture, map capture does not prove removal of every prior primary pixel.

Native route correctness, completed-safe-frame provenance, patch ordering, boundary sampling, memory disposal and black/stale images require later isolated real-game proof. Alternative external-window capture still needs approved-plan divergence before adoption.

## Explicit absences

No arbitrary window internals, window object dumps, control tree, offscreen/occluded labels, unopened/forced tooltip evaluation, raw Widgets draw-call labels, unaudited getter invocation, raw health/need/AI aggregates, hidden totals, generic inspect strings or unsupported metadata. Known ordinary window summaries are only audited `kind` plus optional audited public `label`; no client-selected type/property. Selection uses normal entity eligibility before labels/references. Rendered controls are **absent**, with unsupported/unverified capability until clipping, transforms, occlusion and exact getter paths are proven. Unknown custom/specialist UI can remain screenshot-only; screenshot availability is not structured metadata availability. Missing data never means empty/healthy/zero.

Pure tests cover acceptance dispositions, overload/delayed/unsafe gates, safety truth table, fresh-frame/epoch/release checks and rejected wire additions. They establish contracts only. Later adapters still owe actual UI/source audit, real full-profile normal notifications, lingering-flag/panel transitions and menu/pause/live capture proof.
