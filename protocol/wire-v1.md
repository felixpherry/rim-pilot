# Wire v1 contracts

**Authenticated bootstrap plus read-only baseline observation routes; not verified M1 acceptance.** `shared/Protocol/` compiles into both endpoints and pure tests. Mod lifecycle starts [bounded loopback transport](../docs/transport.md) with native private descriptor publication; CLI discovers/selects/authenticates exact sessions and invokes [health/capabilities](../docs/bootstrap-commands.md) and the typed [observation commands](../docs/observation-commands.md) against validated responses. Source-audited producers for summary, pawns, pawn detail, things, resources, UI, screenshots and a [bounded event ring/canonical notification adapter](../docs/public-events.md) are wired through the scheduler. Limited exact-release Unity Mono evidence exists on one copied fixture (see the [phase-4 evidence summary](../tests/coverage/observation-adversarial.md#phase-4-real-game-evidence-summary)); it leaves `things.list`/`resources` refusing `unavailable`, natural public events, several budgets and hidden-state behavior unmet or unverified, and earlier [menu runtime evidence](../tests/coverage/session-adversarial.md#isolated-menu-runtime-proof) covered only bootstrap. Method enumeration does not advertise runtime availability. [Schema](wire-v1.schema.json), [private discovery contract](discovery-v1.md), [visibility](visibility.md), [fixtures](fixtures/) and [JSON boundary](../docs/json-ingress.md) apply together. [Operation inventory](../tests/coverage/operations.md) separates baseline candidates, screenshot-only specialist surfaces and unverified runtime routes across base game and all five DLCs.

## Framing and authentication

TCP is loopback-only; no HTTP, newline delimiter, BOM, compression, multiplexed streams or server-side paths. Each message: **4-byte unsigned big-endian UTF-8 byte length, then exactly that many bytes**. Header excluded from length. Reject zero, over-ceiling, truncated or invalid frames; close connection. Validate length before allocation. Partial reads are normal; multiple concatenated frames are separate messages. UTF-8 must be strict, JSON grammar/quota rules identical on both endpoints. No reflection/type deserialization. Request envelope is exactly `{v,id,method,params}`; `v` integer 1, `id` 1–64 ASCII letters/digits/underscore/hyphen. IDs correlate responses only; no replay/action semantics. One outstanding request per connection; no pipelining or automatic retry/reconnect. IDs may be reused only after response.

Every connection's first and only authentication attempt is `auth`, params exactly `{session,token}`. Session is expected descriptor identity; token is 32 random bytes encoded as 64 lowercase hex characters. Both must match. Random credentials/session IDs come from cryptographic RNG, never PID/port/save name. Compare fixed-length token with fixed-work loop; malformed auth, wrong token/session/version/method and parser errors have identical `authentication_failed`, no echoed ID, and close. Before auth no game calls or state-bearing errors. Successful auth returns `{session,protocol:1}`; this authorizes connection, not later scope reuse. Reject repeated `auth`. Token never appears in ordinary output, correlation ID, logs, errors, captures or events. Native descriptor permissions/lifecycle are implemented; separate Mono menu proof exercised publication/authentication, not every adversarial or shutdown path. Same-user token is capability, not OS sandbox.

Authenticated request errors may echo only validated correlation ID. Fixed code only, no raw method/arguments/target, input, exception or parser paths. Success `{v:1,id,ok:true,data:{...}}`; failure `{v:1,id?,ok:false,error:{code}}`. Producers use `WireJson.EncodeResponse` with expected method; consumers use `ResponseContracts.Read` with pending method/ID. Explicit response validation is separate from game-field visibility audits. Do not send partial success after frame/response limit failure. Send bounded error if possible then close on transport/write failure.

| Ceiling | Value |
| --- | ---: |
| Request/auth frame | 65,536 bytes |
| Ordinary response frame | 262,144 bytes |
| Screenshot response frame | 4,194,304 bytes |
| Connections per session | 4 |
| Pending validated requests across session | 16 |
| Dispatched requests per Root.Update | 4 |
| Tracked loaded map references | 128 |
| Tracked eligible pawn/thing references | 8,192 (oldest evicted; evicted refs resolve `unavailable`) |
| Request rate / burst per connection, including failures | 8/sec / 16 |
| Auth / request / write deadline | 2,000 / 3,000 / 2,000 ms |
| Idle connection | 10,000 ms |
| Aggregate game-thread observation slice | 2 ms per Root.Update, at most 128 candidates and 1,024 nested fields, shared by all producers |
| Active producer reads / snapshot builds per session | 4 / 1 |
| Active producer memory per session | 2,097,152 encoded bytes |
| Screenshot cadence / in-flight captures | 1/sec session-wide / 1 |

All deadlines monotonic and finite. Header/body share deadline, not renewed per byte. Socket owner closes on timeout even if Stream ignores cancellation. Opt-in transport uses backlog 4, four admission workers, process-wide admission 8/sec (burst 16), 25 ms socket watchdog and 1,000 ms maximum worker drain. Per-connection ingress byte bucket is 524,320 bytes/sec (burst 1,048,640), egress 4,194,308 bytes/sec/burst, including headers; ingress credits reserve before body allocation. See [transport ownership/deadlines](../docs/transport.md). Queue overload `busy`, rate `rate_limited`, deadline `timeout`; drop cancelled work before execution and recheck inside multi-update work. No client event long-poll on game thread. Workers handle only bytes/intents, never Verse/Unity objects. Framing helper does not itself implement listener/deadline/rate/queue policy.

Requests keep ingress limits (depth 16, string 4,096 UTF-16 units, array 256, properties 64, nodes 4,096). Ordinary responses use same structural limits, with larger byte ceiling. Screenshot responses alone permit strings up to 16,384 units for base64 chunks; all other structure limits unchanged. CLI chooses larger profile only for outstanding screenshot request, never by untrusted response hint. Screenshot PNG <=3,141,632 bytes, <=1920×1080 and 2,073,600 pixels, scale finite (0,8]. Concatenate <=256 base64 chunks, each <=16,384 ASCII characters (all non-final chunks exactly that size), decode once locally, validate PNG/dimensions/declared byte length. No server path argument. PNG ceiling leaves room inside frame ceiling. Capture DTO construction is not proof of valid PNG/completed rendering.

## Typed methods and capabilities

All argument objects reject extra/unknown fields, explicit null and coercion. Omitted optional fields mean unavailable/not applicable, **not zero/healthy/empty**. Labels preserve Unicode; max 512 units for labels, 2,048 for public notification text, arrays separately bounded. Empty supported arrays mean explicit empty; unsupported collection absent with capability `unsupported` or `unverified`, not empty. Schema describes potential supported DTO fields, not permission to call an unaudited getter. [Visibility policy](visibility.md) wins.

| Method | Params | Success data |
| --- | --- | --- |
| `auth` | `session,token` | expected session, protocol |
| `health` | empty | minimal `state`: bootstrap/loading/ready/stopping; scope only when valid |
| `capabilities` | empty | <=64 unique `{name,state,schema,reason?}`; state available/unsupported/unverified; optional fixed reason <=256 units |
| `summary` | `scope` | sample, menu/playing scene, build and bounded manifest, supported colony summary |
| `pawns.list` | `scope,limit,cursor?` | immutable eligible page of pawn summaries |
| `pawn.get` | `scope,pawn` | sample + own inspectable pawn detail |
| `things.list` | `scope,limit,cursor?` | immutable eligible page of spawned things |
| `resources` | `scope` | sample + explicitly labeled eligible observed direct spawned stack units; bounded rows |
| `ui` | `scope` | sample + supported selection/window summaries, no arbitrary internals |
| `screenshot` | `scope` | separate completed-render identity + bounded PNG |
| `events.read` | `scope,limit,cursor?` | bounded retained public/lifecycle page, next cursor |

Map methods require `game` + `map` in scope. Other observations use exact root and optional game (absence must match menu); no silent current-map default. `health` and `capabilities` are authenticated bootstrap exceptions: no pawn/map/manifest/UI/capture contents, no unsafe developer data. `available` means actual implemented/audited route/field, never schema existence. Current producer marks `auth`, `health`, `capabilities` and (when its audited producer bound) `summary` available; the other seven baseline observation methods remain unverified. Known specialist gaps explicitly unsupported; untested adapters unverified. Health `ready` means current main-thread scheduling checks passed, **not** audited observation/developer safety or runtime acceptance; health adds the root/game scope (no map) only while an ordinary read would currently be authorized; it is the cold-start handle for `summary`, which then supplies map IDs. Loading returns minimal `loading` when dispatched, or a fixed failure if transitions/deadlines invalidate the queued request. Baseline health is visible health-card rows, not raw health percentage/hidden diagnoses; needs are shown needs; jobs only independently permitted public reports. No raw inspect string, internal job target, arbitrary type/property or debug metadata. Rendered control metadata absent until clipping/occlusion proven.

`screenshot.map_view` follows screenshot producer binding (`available` or `unverified`) with `schema:"screenshot-v1"` and a fixed `reason` documenting the user-approved weaker paused/live proof: frame advanced past request, capture GPU fence passed, safety/readiness/scope/size/scale clean throughout hold-then-release. Map images show what the game displayed for that frame under depth-only primary clear; they do not prove every primary pixel was replaced. Whole-frame provenance holds for menu capture only. Unsafe state, scope/size/scale or render-mode change, timeout and all other refusals remain; no forced clears, camera changes or external fallback. Actual paused/live pixel proof remains for subsequent batches; world/specialist capture remains unverified. Wire image fields and limits are unchanged. Capability reasons are fixed public implementation limits, not target-specific refusal details.

Named action/raw input/debug methods return `forbidden_method`; all other unknown names `unsupported_method`. Neither can reach a generic dispatcher. No grants/actions in v1. Capability schema IDs are fixed project identifiers, not client-selectable runtime types.

## Identities, readiness and timing

Identity forms: `s_` session, `r_` root generation, `g_` game generation, `m_` loaded map generation, `c_` individual sample/render capture, `p_` pawn, `t_` thing, `q_` immutable snapshot/page cursor, `e_` event cursor. Every suffix is independent random 128-bit lowercase hex, **not** counter/index/game numeric ID, position, hash of private data or serialized object reference. Tokens/cursors cannot be synthesized by changing offset. They are scoped references, not auth substitutes. Entity IDs allocated only after eligibility; unknown/stale/hidden/ineligible entity lookups all `unavailable` with identical payload. Map unknown/hidden/unloaded also `unavailable`; do not use detailed map-existence errors. `stale_scope` reserved for authenticated already-public session/root/game mismatch.

Bridge tracks **reference equality**, not overloaded equality or reused game IDs: rotate root on Current.Root replacement; rotate game on Current.Game replacement, observed transition/load/menu invalidation even if same object later returns; rotate map on removal/replacement/re-addition. Root/scene/load transition invalidates all subordinate refs/snapshots/cursors/pending work. Game rotation invalidates its maps/entities. Removed maps cannot be resolved by recycled numeric IDs. Recheck expected session, scope, readiness and visibility at execution, page publication and capture completion. No reference/scope tracking updates from background threads. Audited worker transition observers may invalidate a BCL-only revision/queue; reference sampling remains game-thread-only. Current dispatcher conservatively rotates all scopes on any transition or Maps-list mutation, including remove/re-add with identical final references. See [dispatch boundaries](../docs/read-dispatch.md).

`AnyEventNowOrWaiting` => `not_ready`, even if `ShouldWaitForEvent` false or ticks unchanged. Null/invalid root, transition, missing required game/map or uninitialized visibility => `not_ready`/uniform target `unavailable`, never partial collection reads. Developer restriction takes precedence and returns `observation_refused`; do not toggle settings. [Publication/developer/safe-frame policy](observation-safety.md) and its finite [safety manifest](developer-safety-v1.json) define required evidence, known panels and lingering flags; no runtime sampler exists yet.

Structured `sample` contains `{scope,capture,frame,phase:"root_update_postfix",tick?}`. The phase tag denotes sampling **after the complete derived Root_Entry/Root_Play.Update**, through its last finalizer, not the base Root.Update postfix (which precedes UpdatePlay). This remains before later GUI/rendering, not end-of-render or an atomic end-of-tick promise. Frame is engine frame counter sampled there, tick valid only with game; neither proves rendered image or atomic multi-update traversal. Only `summary` is produced so far; historical synthetic fixtures establish shape, not callback provenance. Sample `capture` differs from screenshot `capture`. Screenshot has `phase:"completed_render"`; never label separately sampled JSON same rendered frame because frame integers match. Producer requires `CompletedRenderStamp`: frame strictly newer than request, scene-specific proof (menu whole-frame or user-approved map displayed-frame), capture fence passed, unchanged private safety epoch/scope/size/scale and release recheck. Evidence validation is not native/render-boundary proof; that remains capture-adapter work.

## Eligible snapshots and pagination

No client offset, raw source total, scanned count, candidate cursor, map-lister index/hash or hidden identity on wire. `limit` 1–64. First request omits cursor; later requests repeat exact scope/method/limit and opaque `q_` next token. Snapshot field identifies frozen eligible DTO vector; page cursor separately maps immutable page start. Retain at most 2,049 page boundaries per snapshot (including empty tail); never one allocation per repeated poll. Cursor reusable/non-consuming until expiry, no global destructive reader state. `complete` refers to **end of frozen eligible snapshot**, never all raw candidates or full game coverage. No `total` field. Only fully built, audited snapshot may yield pages; no partial scan pages or “more candidates” hint.

Before retaining anything: validate type/field/visibility, project approved primitives, then aggregate/page. At most one active snapshot build per session. Snapshot max 2,048 eligible records, 2,097,152 encoded DTO bytes, four retained snapshots (8 MiB encoded DTO budget, bounded object overhead), five-second monotonic lifetime. Max 16,384 candidates examined per build, session-wide 128 per update and 2 ms, overall request deadline 3 sec. Source access itself must be bounded; never `ToList`/sort/copy raw entire lister before charging candidates. Continue bounded traversal over updates only with stable source identity/revision; any mutation that could skip/duplicate examined entries aborts rather than claim complete. Exhaustion/time/source instability => uniform `unavailable`/`timeout`, discard all partial DTOs, never exact source/candidate count or special hidden-budget status. Eligibility result must be supplied by audited adapter, not transport.

Publication stamp describes final validation/copy boundary. DTO fields may have been gathered over several updates: snapshot is frozen historical observation, **not atomic live simulation snapshot**. Adapter revalidates eligibility of entire retained eligible vector (bounded 2,048) before initial and subsequent page publication, within shared slice/deadline. If any member no longer eligible, source scope/object replaced, traversal invalidated or relevant safety/authorization epoch changes, invalidate whole snapshot. Do not silently remove rows, mix new values or disclose which row invalidated. Ordinary value changes after publication do not rewrite historical DTOs; request fresh snapshot for current values. Cached raw game objects never serialized. ListerThings add/remove hash alone insufficient for visibility/field validity. Cursor expiry/eviction/wrong query binding => uniform `cursor_expired`, no offset/owner/source details; scope invalidation may instead require scope refresh.

Fixed output schemas remove direct hidden counts/positions, **not a claim of constant-time game processing**. Resource failure/latency must not encode exact scan progress. Test dense hidden populations and repeated bounded requests; if an adapter cannot meet data-channel noninterference, keep route unavailable rather than publish a truncated prefix.

## Events and errors

Events are sanitized retained history, not current-world DTO lookup. First `events.read` without cursor starts oldest retained public event; makes no pre-bridge completeness claim. `e_` maps private scope + retained sequence boundary, no public raw sequence counter or scan offset. Each page <=64 items; `next` is supplied even for empty tail, immutable reusable/non-consuming across readers. Empty read at tail returns same boundary. Ring caps 256 entries/262,144 encoded bytes; max128 remembered cursor boundaries, finite five-second cursor lifetime; eviction/expiry can require resync. Event cursor cannot consume history for another reader. Internal sequence advances only for accepted sanitized public/lifecycle publication, never hidden/rejected attempts. Scope transition invalidates cursor (`cursor_expired`, bootstrap resync); retention overflow/old boundary reports `event_gap` with no lost count, client discards cursor and resyncs summary then reads fresh history. Invalid tokens indistinguishable from expired tokens. [Publication policy](observation-safety.md#accepted-public-publication) excludes delayed/rejected/duplicate/restored/unsafe attempts, requires canonical audited public acceptance and constrains retained availability. Lifecycle text is fixed `observation_ready`, `scope_changed` or `observation_resumed`, with no label or internal diagnostics. The [event adapter](../docs/public-events.md) implements bounded retention and installed-source canonical acceptance/availability witnesses for exact Message/StandardLetter types; actual full-profile Mono acceptance remains unverified.

| Code | Meaning / recovery |
| --- | --- |
| `invalid_frame`, `invalid_json`, `invalid_request`, `version_mismatch` | Invalid framing/grammar/schema/version; fix client, no game execution |
| `authentication_failed` | Uniform pre-auth failure; connection closed; never auto-retarget |
| `forbidden_method`, `unsupported_method` | No control route / unknown route; no fallback |
| `not_ready`, `observation_refused` | Loading/invalid scene / safety refusal; no observation payload |
| `unavailable` | Uniform unknown/hidden/unsupported target or safe bounded projection unavailable; no existence/count clue |
| `stale_scope` | Public session/root/game changed; explicitly refresh same authenticated session |
| `cursor_expired`, `event_gap` | Restart eligible query / explicit event resync; no missing count |
| `busy`, `rate_limited`, `timeout` | Finite resource/deadline rejection; no latent work |
| `response_too_large`, `internal_error` | No partial output; no internal exception detail |

The phase-4 real-game runs (see the [evidence summary](../tests/coverage/observation-adversarial.md#phase-4-real-game-evidence-summary)) exercised these routes on one fixture; real event-gap, thing-cursor, second-map binding, full-profile hidden-state and capture/first-use budget behavior remain unproven or unmet, and screenshots decode as complete 1280x720 PNGs only (1920x1080 refuses by design). A route reported `available` by `capabilities` means only that its producer is registered, not that the route succeeds on a given game. Host .NET socket/deadline tests cover the opt-in transport component, not installed Mono interruption latency.
