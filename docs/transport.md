# Bounded loopback transport component

`shared/Protocol/LoopbackTransport.cs` is a game-independent transport owner. The mod's [process lifecycle](mod-lifecycle.md) now starts it on one background owner after game-thread quitting registration. CLI session discovery authenticates exact endpoints. [Main-thread dispatch](read-dispatch.md) produces authenticated [health/capabilities](bootstrap-commands.md), but no baseline observation producer is enabled. Ordinary reads fail closed rather than return invented data. Host tests supply synthetic scheduling/game evidence; they do not establish Unity Mono or game behavior.

## Ownership and admission

`LoopbackTransport.Start` applies the shared private directory policy, owns its native registry handle, binds one IPv4 socket to literal `127.0.0.1` with an ephemeral port and backlog **4**, then atomically publishes a fresh cryptographic session/credential through `LinuxPrivateDirectory.Publish`. No externally configured bind address, port or credential exists.

Four persistent background accept/serve workers bound admitted connections to **4**, including unauthenticated peers. Each uses synchronous `Socket.Accept`, then waits on async framed I/O off the game thread. Installed Mono `EndAccept` checks listener disposal before returning its accepted socket; avoiding that path prevents an accepted socket from being stranded in an inaccessible async result during a close race. Excess peers wait in the finite kernel backlog; no worker is created per rejected peer. Kernel backlog rounding and scheduling are OS behavior, not an exact simultaneous-client guarantee. Process-wide admission has a monotonic **8/sec, burst 16** bucket; rejected admissions close without response and wait **125 ms** before their worker accepts again. Requested socket send/receive buffers are **16,384 bytes**; Linux may adjust/double these. Application memory ceilings come from framing and admission, not an assumed exact kernel buffer size.

Each connection gets exactly one authentication attempt through the existing `Authentication` contract. Wrong session/token/version, malformed JSON/framing and wrong initial method produce the same fixed `authentication_failed` response when writing remains possible, without ID, then close. Authentication proves exact random session, not PID/port identity. A later `auth` is invalid; scopes naming another session are rejected before dispatch. Root/game/map scheduling checks belong to the main-thread dispatcher; audited observation/developer safety remains unimplemented.

Only typed `Request` intents enter `PendingReads` (capacity **16**). No wire closures, reflection dispatcher or game objects cross this boundary. One request is processed at a time per connection; already-buffered pipelining is rejected before dispatch/publication. Disconnect/expiry cancels queued and dequeued intents. Queue removal happens in connection cleanup; stale entries are pruned on admission/dequeue. `TryTake` is not authorization: the consumer must recheck cancellation, absolute deadline, current scope/readiness and developer safety before and within work. Transferred primitive response data must not be mutated by its producer afterward. Cancellation callbacks must be nonblocking; they execute on the cancelling thread.

## Deadlines and bytes

All stage deadlines use `Stopwatch.GetTimestamp`, not wall time. Authentication: **2,000 ms**, including header/body and auth reply. After authentication, idle first-byte wait: **10,000 ms**; first byte starts a **3,000 ms** absolute request deadline shared by remaining header/body, queue/execution, validation and publication. Each write is capped at **2,000 ms**, or the earlier current deadline. Partial progress never renews a deadline.

A **25 ms** watchdog checks expiry and peer EOF, closes the owned socket first, then signals cancellation. EOF inspection (`Poll` followed by `Available`) is serialized against starting receives and skipped while a receive is active: otherwise the receiver could drain readable bytes between those two calls and be mistaken for a disconnected peer. Active reads detect their own EOF; the watchdog still enforces their absolute deadlines. Queued/executing work and writes retain watchdog EOF detection. This is a native pending-I/O backstop, not reliance on stream token cooperation. Completion paths also recheck monotonic expiry. Timer/thread scheduling is not a hard real-time guarantee; actual Unity Mono interruption latency remains unverified. An expired/disconnected socket can close without a final error frame; no partial response counts as success.

Requests retain the **65,536-byte** frame ceiling, ordinary responses **262,144**, screenshot responses alone **4,194,304**. Frame header is four bytes. Validated ingress length reserves byte credits **before body allocation/read**. Per-connection request bucket: **8/sec, burst 16**, including auth/failures. After authentication, the first header byte triggers rate admission, before consuming the remaining header or allocating/reading the body. Denied requests never enter the dispatch queue. The terminal `rate_limited` error has no request ID because the rejected envelope was not read; delivery is best-effort like other transport errors, not a reason to drain rejected input or retry automatically. Independent ingress byte bucket: **524,320 bytes/sec, burst 1,048,640**. Egress bucket: **4,194,308 bytes/sec and burst**, charged before any write. These include headers. Typed response validation occurs before its frame header is sent; screenshot's larger profile never widens request/auth parsing. Resource failure returns a fixed bounded error where possible, then closes rather than accumulating delayed retries.

## Cleanup and diagnostics

Shutdown closes the original listener directly (avoiding Mono `TcpListener.Stop` replacement sockets), closes admitted peers, clears pending intents and waits at most **1,000 ms** for workers. `WorkersStopped` distinguishes observed drain from a timed-out drain. Startup failure, including publication or partial worker startup, follows the same socket/drain/owned-record cleanup. Shutdown is idempotent. Reusing a disposed transport is unsupported; restart creates fresh identities.

Only this instance's unchanged native ownership receipt authorizes descriptor removal. Replaced/uncertain records and quarantined crash leftovers remain untouched; no timeout/PID-based stale cleanup occurs here. Future discovery consumers must ignore `.pending-*` workspace names, not parse or delete them as session records. See [native filesystem boundary](native-filesystem.md).

No peer input, token, endpoint descriptor, private path, parser message or exception detail is logged. Startup errors use fixed `Local transport unavailable.` without an inner exception; wire errors use fixed codes. Validated correlation IDs may be echoed, except the active credential is refused as an ID. Transport `ToString` is fixed text, not a credential dump.

`tests/JsonIngress/TransportTests.cs` exercises host-native private publication plus real .NET loopback sockets: authentication negatives, framing/JSON, typed replies, admission/rate/byte bounds, partial/idle/request/write deadlines, disconnect cancellation, pipelining, startup failure boundaries, replacement preservation and repeated fd/worker cleanup. The watchdog receive/EOF interleaving has a deterministic regression: the unguarded check cancels an open peer after its readable byte is drained, while the guarded check stays live and still detects actual EOF after receive ownership ends. Burst tests retain the original split-frame response assertion and separately withhold the rest of the header/body or leave it unread, requiring a complete exact `rate_limited` response, closed socket and no denied dispatch on the tested healthy host sockets. Synthetic screenshot bytes are not image/render evidence. Configured net472 compilation is separate from actual Mono/game acceptance.
