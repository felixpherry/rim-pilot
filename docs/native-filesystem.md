# Native private discovery storage

`shared/Protocol/LinuxPrivateDirectory.cs` is a shared Linux x86-64/glibc filesystem boundary, compiled into the net472 mod and CLI. It implements storage, not a listener, authenticated liveness, CLI discovery commands or stale-record collection. Host-native tests and net472 compilation are not Unity Mono/game execution evidence.

## Audited API and ABI

The boundary uses Cdecl `libc` P/Invoke with explicit UTF-8, NUL-terminated byte arrays, 32-bit uid/mode/flags, 64-bit ssize_t/off_t and owning SafeHandles. Runtime checks require Linux, x86-64 and little-endian LP64. The installed Mono library map resolves `libc` to `libc.so.6`; managed directory/file creation security overloads in that runtime discard their security parameters. They are not used here.

Audit inputs were installed glibc source headers `bits/struct_stat.h`, `bits/typesizes.h`, `bits/fcntl.h`, `bits/fcntl-linux.h`, `bits/dirent.h`, kernel UAPI headers `linux/openat2.h`/`linux/fs.h`, installed libc symbol implementations, and installed Mono Directory/FileStream source and library mapping. The installed kernel tree provides headers, not `fs/namei.c`: namespace behavior is tested against the running kernel rather than claimed from unavailable implementation source. No game source or native library is copied into this repository.

`tests/native/private-fs-abi.c`, compiled against installed public headers, independently checks every consumed stat offset, dirent offset, I/O width, mode and namespace flag. Python repository tests run this check with `cc -std=c11 -Wall -Wextra -Werror`. Tests require a C11 compiler and glibc development headers. The C# native suite then exercises the actual P/Invoke calls. Neither check establishes another platform's ABI. The runtime requires exported `fstat` and `renameat2` (glibc 2.33+); missing symbols, unsupported rename semantics and metadata failures cause fixed refusal, not a weaker fallback.

## Directory and record guarantees

- Selection uses the shared [runtime policy](../protocol/discovery-v1.md). `LinuxPrivateDirectory.Open(xdgRuntimeDirectory)` selects once and retains opened descriptors. It never reselects or scans a second registry after an operation fails.
- Traversal starts at `/`, uses one component per `openat` with `O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC`, and retains every ancestor fd. Ancestors must be root/effective-UID owned and not group/world writable, except root-owned mode-01777 sticky ancestors. Root itself cannot be writable by others. Private base/registry components require exact effective UID, directory type, nonzero link count and mode 0700, including rejection of special mode bits. Fallback additionally verifies actual root-owned mode-01777 `/tmp`.
- Registry subdirectories are created with mode 0700 in the creation syscall, then verified. Existing unsafe directories are never repaired or adopted. Pathname-to-fd identity and metadata are rechecked before/after relevant operations, so a detached/replaced directory is not silently treated as the selected registry.
- Record names are exactly the session basename from the descriptor contract. `O_PATH | O_NOFOLLOW` checks type before an I/O open. The subsequent `O_NOFOLLOW | O_NONBLOCK | O_NOCTTY | O_CLOEXEC` open must identify the same regular inode. Regular file, effective UID, exact 0600 and one hard link are required before reading. Symlinks, directories, FIFOs, unsafe modes and hardlinks fail closed.
- Size is checked before allocating a bounded 1025-byte buffer. Reads accept only the exact observed length, check an overflow sentinel and revalidate inode/content metadata and directory identity. Short/interrupted reads fail; they are not partial successes or indefinite retries.
- Enumeration owns a separate directory stream, validates UTF-8 names, ignores only `.`/`..`, and reserves the shared entry budget for everything else, including private workspaces and unrelated names. It never trusts `d_type`, sorts an unbounded list or returns a budget-truncated prefix. A caller must filter valid descriptor basenames before spending its separate record-read budget.

## Publication and ownership

`Publish(descriptor)` creates an exclusive random `.pending-<hex>` workspace with mode 0700, then an exclusive no-follow file with mode 0600. Owner/type/mode/link checks precede the first secret write; there is no create-public-then-chmod interval. Restrictive umasks can cause safe refusal, never permission repair. Secret writes and fsync complete before publication; staging metadata/name identity is revalidated. `renameat2(RENAME_NOREPLACE)` publishes the complete record atomically and cannot replace an existing file, symlink or directory. Unsupported filesystem semantics fail closed.

A successful publication returns an opaque `OwnedRecord` receipt holding the original fd, bounded bytes and content metadata. The open fd prevents inode-reuse confusion. Call `RemoveOwned(receipt)` before disposing the receipt and registry. Receipt disposal closes handles and removes only an empty verified workspace; it does **not** delete a published record. Lost receipts/death leave advisory stale records, not deletion authority.

Linux has no compare-inode-and-unlink syscall. Removal therefore validates the original identity/bytes/mode/link/content metadata, atomically moves the name into the receipt's private empty workspace with no overwrite, then validates again before unlinking there. A replacement raced into the source name is not deleted. Failed comparisons restore the quarantined object with no overwrite; if another writer occupies the source, both objects are retained and removal fails. Cleanup never recursively deletes unknown files. Other instances' receipts cannot authorize removal, and connection failure/PID absence never enters this storage API.

## Limits and remaining evidence

The trust boundary excludes hostile processes with the same UID and root: either can already read credentials, mutate private files or change mounts. Retained fd/metadata checks cover the tested namespace replacement windows, not an OS sandbox against such actors. Storage must be on a filesystem that truthfully implements Unix metadata and atomic no-replace rename. There is no managed compatibility fallback.

Atomic publication is not a power-loss durability claim. Files are fsynced, but registry-directory persistence and crash recovery are not established. A crash during removal can leave a private quarantined record; interrupted staging can leave an empty/private workspace. Discovery must ignore these non-record names, retain uncertain artifacts and still apply its entry ceiling. Filesystem/kernel latency, including fsync, is not hard real-time; storage calls do not belong on the game frame loop.

Scratch-only native tests cover creation under umask 000/077, refusal under 0777 before secret writes, owner checks, exact modes, symlinks at every directory level, FIFO/hardlink/size/name refusal, Unicode and invalid UTF-8, read/publication/removal races, restoration collision, concurrent publication, finite enumeration/read budgets and repeated fd cleanup. No game launch is needed for these host tests. A separate authorized isolated Unity Mono menu run exercised actual private native registry creation/publication and CLI access with verified directory/file modes and exact game/CLI environment. This establishes the exercised binding/startup path, not the adversarial host matrix under Mono, owned-record shutdown removal or power-loss durability; see [runtime evidence](../tests/coverage/session-adversarial.md#isolated-menu-runtime-proof).
