# M1 visibility source audit

Contract: [normal-player field/type rules](../protocol/visibility.md).

**Status:** source-audited observation adapters and typed CLI commands now exist, with host regressions and configured net472 compilation. Actual Mono/full-profile availability, UI equivalence and hidden-state safety remain unverified; see [evidence matrix](../tests/coverage/observation-adversarial.md). Private inspection covered installed RimWorld 1.6.4871 rev600 and relevant selection, health, needs, report and resource APIs. Source symbols below locate the behavior without distributing proprietary code, local dependencies or private paths. Local decompilation line numbers are intentionally not public API identifiers.

The approved standalone plan and milestone scope require useful off-camera, player-knowable observations with no gameplay/UI changes. M1 does not authorize M2 controls, M3 co-play, M4 complete specialist coverage or M5 qualification. All five DLCs remain in scope; missing scenario/type evidence must remain visible as a gap. These documents establish the visibility boundary only. They neither implement the adapters nor satisfy baseline/acceptance requirements by marking fields unsupported.

## Admission building blocks

[Exact projection admission audit](projection-admission.md) documents private policy gates and bounded primitives. No observation route or baseline family is completed by these building blocks alone. Remaining approved fields retain their tasks; unknown providers/patches are family-level unverified gaps, never audited empty results.

## Target gates

Map/target gates (`mod/Observation/TargetGate.cs`, `GameTargetAccess.cs`) now guard summary counts, pawn list/detail, things/resources and selection. Installed 1.6 source supports these choices:

- **Map access.** The colonist bar lists every loaded map, including empty ones, so a map in the current Game's map list is inspectable regardless of current map, home status or pocket-map kind. The gate also requires non-disposed geometry whose cell index matches the map size, no map generation in progress, and a created fog grid of exactly that many cells. Map IDs are allocated and resolved only through this gate, rechecked on every use.
- **Initialized fog.** `FogGrid.IsFogged` returns false for an uncreated grid or out-of-bounds cell, and the bit array's read is unchecked in release builds. The gate reads the private grid's created/length witness, proves each index in bounds, and never counts an out-of-bounds cell as unfogged.
- **Direct spawn.** The private map-index field must point at exactly the tracked map, and `holdingOwner` must be reference-identical to that map's non-null `spawnedThings` container. Installed `Thing.SpawnSetup` inserts direct things into this container; a null holder is not normal direct-spawn evidence. Other map, carried and enclosed containers refuse without traversing holders. Both holder and map-container identities are witnessed, including excluded members. The gate never calls `Spawned` (it logs on a bad index), `SpawnedParentOrMe`/`ParentHolder` (holder traversal) or held positions.
- **Footprint.** One-cell targets need their own cell unfogged; multi-cell targets need any in-bounds occupied cell unfogged, matching map-click selection. Footprints over 256 cells are unavailable, and cells are charged as nested work before fog is read.
- **Type.** Exact runtime types only (no inheritance), selectable definition required.
- **Pawn concealment.** Normal hidden-from-player rule: own-faction pawns stay eligible even when invisible. Any other pawn (enemy, visitor, prisoner, wild animal) is hidden when some hediff has an invisibility component whose definition is not marked visible to the player and the pawn is not currently revealed. Whether it is revealed depends on downed/stun/fire/foam/disruptor state, carrying, holding platforms, recent damage and fade timing, and that getter writes a cache. So the gate reads plain fields only and treats every non-player pawn carrying such a component (any subclass, any position in the list, missing properties included) as unavailable, even while revealed. Hediffs and components are charged as nested work first; lists over 256 hediffs or 32 components per hediff are unavailable. The debug "show hidden pawns" switch is never honored here; the developer-safety sampler refuses observation while it is on. A patch on the hidden-from-player check or map-click selection fails the gate closed.
- **References.** Pawn/thing refs are allocated only after the gates pass, bound to one map and kind, capped at 8,192 per generation (oldest evicted) and dropped on any root/game/map rotation. Resolution returns a candidate only; callers rerun every gate.
- **Errors.** Root/game mismatch is `stale_scope`. Unknown, removed, hidden or inaccessible maps and entities all return the same `unavailable`.
- **Patch closure.** Every getter/helper the game gate calls is checked unpatched once per frame; any patch fails closed.

Host tests cover the pure gates, reference table and dispatcher scope split. Configured net472 compile covers the game adapter. Neither is Mono/game proof.

## List witnesses

Map list sources (`mod/Observation/GameListSource.cs`) give the snapshot store and bounded counts two witnesses, both read from installed 1.6 source:

- **Structure.** The raw list itself: all spawned things (`ListerThings.AllThings`, assigned once in the constructor) or the private spawned-pawn list behind `MapPawns.AllPawnsSpawned` (never the shared helper result lists). Mono's list enumerator rejects any add, remove, clear, indexer write or sort after capture, even when the final references match. A replaced list reference also counts. Once changed, the witness stays changed.
- **Eligibility revision.** Two parts. First, a fog edit counter bumped before and after every installed fog-bit writer: unfog worker, refog, set-all-fogged, load and dispose. The internal unsafe fog accessor's callers only read. If any hook fails to install, the counter is unavailable and whole-list revalidation must fit one update (1,024 nested fields), so larger lists cannot publish. Second, a per-member witness captured with every gate decision (eligible or not): spawn index, holder, definition, position, rotation, faction, and for pawns outside the player faction the hediff list identity and version. Hediff lists are mutated directly from many call sites without a common notification, so the list version is the witness, not a hook. Hediff component lists are only created with the hediff. Any shared edit, changed or unreadable witness, or failed patch-closure check advances the revision and forgets every witness, which restarts a multi-update pass from its first member.
- **Bounds.** At most 2,048 member witnesses per source; a full table makes the gate result unusable. Comparison reads only fixed plain fields and closure-checked field getters, but currently walks the entire table synchronously without charging nested work. This is not a constant-cost mutation revision or a proven budget-fitting interval witness for larger scans. Fog/list counters alone do not cover movement, stack or other unchanged-list decision changes; comparing only the latest slice misses changes to earlier excluded members. Host mutation controls reject both shortcuts. Larger raw scans remain disabled pending a complete audited revision or bounded stable-index design; host controls do not establish runtime usefulness or timing.
- **Limits.** Map access changes (map add/remove/dispose, loading) already rotate scopes and expire everything. Moving pawns change their witness, so during live play a large pawn list may only complete within one update. Third-party code writing fog bits outside these methods, or patching mid-pass, is not covered (see risks).

## Summary

`summary` (`mod/Observation/GameSummary.cs`, pure DTO assembly in `SummaryProjection.cs`) is the first registered producer. It runs only after the dispatcher's developer-safety, readiness, epoch and exact root/game scope checks; health supplies that scope while observation is authorized. Installed 1.6 source supports these reads:

- **Scene, build, tick.** Menu vs playing follows the sampled Game. Build is the version-with-revision static field. Tick is the tick manager's game-tick field; sample frame is the engine frame of the releasing update.
- **Paused.** The tick manager's paused getter: user time speed, or forced pause from open force-pause windows, long events, the tile picker, gravship cutscene/landing confirmation or map-gen debug mode. All of that closure is plain fields and bounded scans; if any of it is patched or throws, `paused` is omitted, never guessed.
- **Maps.** Every tracked map that passes the map-access gate, in game order, with its gated `m_` ID, size, and label. Settlements (exact types) show their name field; every other parent uses its public world-object definition label, because sites, space maps and mod parents override the label with unaudited logic. More than 64 maps omits the list. `currentMap` is the game's current-map field, mapped through the same gate.
- **Own-pawn count.** Per map, exact-type `Pawn` entries of the private spawned-pawn list that are [own pawns](#own-pawns) and pass every target gate. Each candidate is charged before it is read, and every candidate (counted or not) is witnessed through the list source, so the count is published only if the list and every witness are unchanged at release. Lists over 2,048 pawns, a missing player faction, a full witness table, the 16,384-candidate read cap or more than two restarts omit that map's count rather than publish a partial one.
- **Manifest.** Running content packs in load order: player-facing package ID and name fields. DLCs are the official non-core packs. Any invalid entry, or more than 256 mods / 16 DLCs, omits that list. No mod versions (that needs a metadata lookup outside this audit).
- **Closure.** Every non-field getter used here is checked unpatched in the releasing update; a patch fails the summary (`unavailable`) or omits `paused`.

Header facts are read in the releasing update; counts may span updates. Host tests cover DTO shape, health scope gating and capability advertising; configured net472 compile covers the game producer. Neither is Mono/game proof.

## Own pawns

`pawns.list` and `pawn.get` (`mod/Observation/GameOwnPawns.cs`, pure rules/DTOs in `PawnProjection.cs`) run after the same dispatcher checks plus a map-scoped request whose map passes the map-access gate. Installed 1.6 source supports these reads:

- **Who counts.** Exact-type `Pawn` entries of the private spawned-pawn list (never the shared helper lists such as free colonists) whose faction is the player's and that have no guest host, or are colony slaves (host = player, slave status). This covers colonists, slaves, animals, mechs and mutants alike; prisoners, guests and visitors are excluded because their faction or host differs. Contained, carried and caravan pawns are not in the spawned list and also fail the direct-spawn gate. Every candidate is charged before it is read; excluded candidates are still witnessed.
- **Gates.** Each own pawn passes the full target gate (direct spawn on this map, selectable definition, any unfogged footprint cell). Own pawns skip the concealment check, matching normal hidden-from-player rules. Guest host/status joined the list witness, so a capture or release expires the snapshot.
- **Label.** Equivalent to the colonist-bar short label (`LabelShortCap`) without calling it: a turned mutant's name prefix, then the short name (exact `NameTriple` nickname getter or `NameSingle` name field), or for unnamed pawns the best kind label from life-stage and kind-definition label fields by gender (the cached life-stage index only, never a recalculation), then first-letter capitalization. Unknown `Name` subclasses, an uncached life stage, markup or tagged-string markers, or oversized/invalid text refuse the pawn.
- **Status.** Fixed tokens `downed`, `dead`, `drafted` from the health-state and draft fields; an empty array means none apply. No mental state, health summary or inferred condition.
- **Closure.** The normal label/status getters (`LabelShortCap`, `LabelShort`, `LabelNoCount`, `LabelPrefix`, `KindLabel`, both `BestKindLabel` overloads, `CapitalizeFirst`, name/mutant/health/draft getters) are checked unpatched once per frame. Any patch, or an eligible own pawn that cannot be projected, makes the whole request `unavailable`, never a silently shorter list.
- **List paging.** The first request builds the full eligible list into an immutable snapshot across updates (restarted at most twice if the list changes mid-build), revalidates every member through the own-pawn rule and target gate in the releasing update, then returns the first page. Cursor requests revalidate the retained snapshot and return the next page; any member that is no longer eligible expires the snapshot (`cursor_expired`). Rows are historical values from the build.
- **Detail.** `pawn.get` resolves an `p_` reference only as a candidate and reruns the own-pawn rule, target gate and projection in the releasing update. Unknown, evicted, moved, hidden or no-longer-own pawns are uniformly `unavailable`. Detail adds shown `needs`, `health` rows, `gear` rows and independent public `job`/`lordReport` text (below). Any unverified family is omitted without dropping the rest of detail.

Host tests cover the pure rules and DTO contract; configured net472 compile covers the game reader and producers. Neither is Mono/game proof.

## Shown needs

`pawn.get` adds `needs` (`mod/Observation/GameNeeds.cs`, pure order/arithmetic/rows in `NeedsProjection.cs`), read in the same releasing update as the pawn's gates. It reproduces what the normal needs tab draws, without drawing or opening it:

- **Which needs.** The tab shows when the pawn has a needs tracker with at least one need (its animal/insect-faction and holding-platform branches cannot apply to directly spawned own pawns). The list is every need whose `ShowOnNeedList` is true, sorted by descending `listPriority` exactly as the installed Mono `List.Sort` does (fixed swaps for 2-3 entries, insertion sort for 4-16; more than 16 shown is unverified). Then the separate mood pane: the exact `tracker.mood` object, shown even though its definition sets `showOnNeedList=false`; a mood already in the list is reported once. No pane exception for any other hidden need.
- **Audited classes.** Exact `Need_Rest`, `Joy`, `Beauty`, `Comfort`, `RoomSize`, `Mood`, `Suppression`, `Deathrest`, `Play`, `Sadism`, `Learning`, `Chemical` (base list flag, level field, maximum 1); `Need_MechEnergy` (maximum = race `maxMechEnergy`); `Need_Outdoors`/`Need_Indoors` (hidden when dead or when the other preference applies, mirrored by need-definition identity); `Need_Chemical_Any` (shown only with an unsuppressed drug-desire trait of degree 1 or more, `TraitSet.GetTrait` order); `Need_KillThirst` (biological age 13+ and base flag); `Need_Food` (below). Binding asserts each class's declaring implementation of `ShowOnNeedList`, `CurLevel`, `MaxLevel`, `CurLevelPercentage` and `LabelCap`. Any other class (including Royalty's `Need_Authority`), a derived tracker or a definition whose `needClass` differs makes the whole family unverified for that pawn.
- **Royalty `Need_Authority` stays unaudited (checked 2026-10-27).** Its list flag is `IsActive`: royalty tracker, spawned, `Map.IsPlayerHome` and `CanRequireThroneroom`. `IsPlayerHome` falls through to the Odyssey grav-engine lookup, which writes a static per-tick cache and can walk every holder on the map recursively; `CanRequireThroneroom` calls `IsQuestLodger`, which scans every extra-faction quest part through a shared static list. Neither is a bounded, write-free mirror, so a pawn carrying this need keeps the whole-family omission.
- **Row.** Label = `Def.LabelCap` mirrored from the plain `label` field with first-letter capitalization; an existing label cache must agree; markup is refused. Level = level field / maximum, finite in [0, 1]; non-finite, zero/negative maximum or overfull levels are unverified, never clamped or zeroed.
- **Food maximum.** In play, `Need_Food.MaxLevel` asks the MaxNutrition stat with a 15-tick cache. A cache entry younger than 15 ticks is read (never written) and used, as the normal tab would. Otherwise the value is recomputed from fields, mirroring `StatWorker.GetValueUnfinalized`/`FinalizeValue` order: definition base value, no-skill offset/factor, hediff offsets then factors, `BodySize` (life-stage factor × race base) and life-stage food factor, scenario factor (`Scenario.GetStatFactor`, called), round-to-five, rounding and clamp. Admitted only when the stat has exactly the official two parts and no skill/capacity/stat/post-process inputs, the pawn has no stuff and a cached life-stage index, and no trait degree, gene, precept, conditional affecter, role effect, life stage, worn/held gear or bladelink trait, or current inspiration mentions the stat; every pawn comp keeps the base zero/one stat offset/factor. Hediffs whose stages never mention the stat contribute nothing; a single-stage definition with plain offset/factor (the Anomaly ghoul's ×2) is mirrored; custom `CurStage` classes other than the audited band node and disruptor flash are unverified. The worker, cache and life-stage index are named private field reads.
- **Never called.** Drawing, tooltips, instant mood, need intervals, `Def.LabelCap`, `CurLifeStageIndex`, `GenesListForReading` (lazy cache) or any stat worker. Called: plain field getters, `AgeBiologicalYears`, `Trait.Suppressed`/`Degree` and the scenario factor loop.
- **Closure and budget.** The card/caller, subclass overrides and the whole mirrored stat closure (about 90 methods) are checked unpatched once per frame; any patch makes the family unverified. Classification charges 4 + 2 per need; food recomputation charges 16 + 2 per input source (and equipment comp) in one step, capped at 512, else unverified.
- **Absent versus empty.** Unverified omits `needs` for that pawn (family gap), never an empty or partial list; `[]` means the tab shows nothing. Identity/status still return.

## Health rows

`pawn.get` adds `health` (`mod/Observation/GameHealth.cs`, pure walk/grouping in `HealthProjection.cs`), read in the same releasing update as the pawn's gates. It reproduces the rows the normal health tab draws for a live pawn, without drawing or opening it:

- **Context.** `ITab_Pawn_Health` passes `ShowBloodLoss(SelThing)`, which is true for a live pawn, so blood loss is not filtered. Dead pawns (corpse context) are unverified. The hidden-conditions and debug-info switches are already refused by the developer-safety sampler.
- **Which rows.** First the missing-part common ancestors, then every other condition whose `Visible` is true. Missing parts are a fresh breadth-first walk from the core part: skip a part when it or any ancestor has a directly added part, stop at the first missing-part condition on a part, else queue its children. The game's lazy list is never built; when it already exists it must match the walk exactly. Missing parts are never shown as flat children.
- **Grouping and order.** Group by body part in first-appearance order, stable-sort groups by `height × 10000 + coverageAbsWithChildren` (whole body first), then group each part by `UIGroupKey` into `Label` or `Label xN`. The part label is the record's custom label or the part definition label, capitalized; whole-body rows omit `part`.
- **Labels.** Mirrored from fields: stage `overrideLabel`/`label` (stage from `StageAtSeverity` over the severity field), comp bracket extras, injury permanent labels, injury source labels and pain category, missing-part removed/destroyed/fresh labels, and `UIGroupKey` (label hash, tended injuries combined as the game does). Fixed keyed strings are looked up in the loaded active language (then the default language) without loading, pseudo-translating or logging. Markup, empty text and differing label caches are refused.
- **Admitted classes.** `Hediff_Injury` and `Hediff_MissingPart` (mirrored overrides), and any official class whose label, visibility, stage, severity, part and group members are exactly `Hediff`'s or `HediffWithComps`'s. Also mirrored: `Hediff_Level` and its subclasses that change nothing else, such as psylink (`label (level N)` or `label xN`); `Hediff_Addiction` (stage 1 only in withdrawal of its chemical need, read from the need's level field; remaining percentage in brackets when the def has a severity-per-day comp); `Hediff_ChemicalDependency` (formatted `{CHEMICAL_label}` base label; severity is the def's initial severity unless the linked dependency gene is active, with the gene found from the cached link or gene lists without filling either cache, and gene activity mirrored from override, minimum age, mutant gene disabling and ghoul fields); `Hediff_Hangover` (hidden while any alcohol high is present). Comps: official comps with base label/visibility members; `HediffComp_Immunizable` ("developed immunity" when its first immunity record is at least 1 and it is not hidden); exact `HediffComp_Disappears`, including its remaining-time label mirrored from nonnegative ticks with the installed short seconds/hours/days/years rounding and optional one-decimal periods (no virtual tick-loss getter call); `HediffComp_SeverityPerDay` only when its hours label is off. Anything else that the normal tab could show (for example psychic bonds, deathrest, labor, modded classes or comps) makes the family unverified for that pawn.
- **Hidden conditions never change field presence.** Concealment is decided per condition before admission, so a condition the normal tab hides cannot drop the `health` family (otherwise presence would reveal the hidden condition). Hidden means exactly: not ever-visible, a current stage exists and that stage does not become visible (`Hediff.Visible`), plus two audited overrides: `Hediff_RotStinkExposure` (lung-rot exposure; additionally hidden while the pawn has a lung rot condition) and `Hediff_PsychicBondTorn` (never visible). The same rule applies to any official unadmitted class whose visibility, stage and severity members are exactly `Hediff`'s (`HediffWithComps`'s visibility only adds comp vetoes, which can only hide more); such a hidden condition is skipped without reading its labels or comps. Missing and added parts are never skipped. A condition the tab could show that is not exactly mirrored (an unadmitted class with its own visibility, stage or severity members, or a visible one with unmirrored labels or comps) still omits the whole family, and that omission is driven by a visible condition, so it reveals nothing hidden. Evidence is host/compile only (the pure decision table, source-shape regressions and the net472 build); no real-game run has carried a lung-rot-exposure or psychic-bond-torn pawn, so this stays unverified in Mono (P4-13-R2). Once lung-rot exposure is visible (past its reveal severity, no lung rot) it is a normal row with the base label.
- **Formatted labels.** Injury tool/body-part-group source labels (`SourceToolLabel`), psylink level and chemical dependency go through a restricted mirror of the simple grammar resolver: plain `{n}`, `{NAME}` or `{NAME_label}` symbols over strings, ints and def labels, then sentence capitalization and the language worker's post-processing. The worker must already exist and be the base worker or the English one (German, French and Korean add their own post-processing and are refused). Any other symbol form, markup or unresolved symbol makes the family unverified.
- **Never called.** Drawing, tooltips, `Visible`, any label getter, `UIGroupKey`, `CurStage`, translation and formatting, need/gene/mutant getters, `GetMissingPartsCommonAncestors`, bleeding/pain/summary aggregates or the debug switches. Called: `BodyPartDef.IsSolid` (pure walk) and plain field getters.
- **Closure and budget.** The tab, card, row/grouping code, missing-part cache builder, every mirrored getter, translation lookup and capitalization helpers are checked unpatched once per frame. One step charges 8 + 4 per condition + body parts + comps (+ needs per addiction, + genes per chemical dependency), capped at 320, else unverified.
- **Absent versus empty.** Unverified omits `health` for that pawn, never a partial list; `[]` means the tab shows no conditions.

## Gear

`pawn.get` adds `gear` (`mod/Observation/GameGear.cs`, pure pieces in `GearProjection.cs`), read in the same releasing update as the pawn's gates. It reproduces the rows `ITab_Pawn_Gear` draws, without drawing or opening it:

- **Tab visibility.** The family is omitted when the normal gear tab is hidden: baby life stage (from the cached life-stage index only), Anomaly entity flesh, Odyssey drone flesh, or a non-humanlike pawn with no equipment tracker, no worn apparel and an empty inventory (only the inventory's count is read for this).
- **Which rows.** Equipment section (when the pawn has an equipment tracker): equipment in list order, then worn belts in worn order, slot `equipment`. Apparel section (apparel tracker, and humanlike or wearing something): other worn apparel ordered by first body-part group `listOrder`, descending and stable, slot `apparel`. Inventory contents are never listed or read.
- **Labels.** `Thing.LabelCap`, mirrored from fields: style override label, else `ThingMadeOfStuffLabel` over the stuff adjective/label and def label (restricted formatter, see health), else def label; then quality, hit-point percent (only for hit-point things with stack limit 1 below max) and the worn-by-corpse mark as `LabelExtras` does; then comp label transforms; then the stack count; capitalized like `CapitalizeFirst(def)`. Forced/locked control annotations are not part of the label and are not sent.
- **Max hit points.** For immutable stats, read the exact standard worker's persistent cache; for mutable stats, read its temporary entry younger than 10 ticks. Neither cache is filled or changed. A cache miss recomputes from the def base, stuff factor/offset, scenario factor and the stat's rounding/clamp, admitted only when the stat has no parts, stat factors or post-processing and the stuff has no quality-dependent modifier for it. Null/unknown workers and missing immutable cache refuse; a cached value is preserved rather than replaced by a fresh computation.
- **Admitted classes.** Thing classes (not pawns or minified things) whose label, hit-point and style members are exactly `Thing`'s/`ThingWithComps`'s. Comps whose label transform and stat offset/factor are `ThingComp`'s; `CompStyleable` only without a source precept; `CompBiocodable` (`Biocoded` formatted when biocoded); exact `CompArt` only without a style source, where its label is unchanged regardless of art activity. This permits ordinary weapons carrying the art comp without reading art contents or invoking `Title` (which can write/log). Anything else, such as unique or bladelink weapon names, art titles or precept-styled items, makes the family unverified.
- **Never called.** Drawing, tooltips, label/quality/style/hit-point/stat getters, `GenLabel` (its shared label cache is never filled) or the stat worker. Called: plain list getters (equipment, worn apparel, comps, inventory count) and the scenario stat factor.
- **Closure and budget.** The tab, row code, every mirrored getter/helper and the shared translation/format closure are checked unpatched once per frame. One step charges 8 + per item (18 + comps, definition/stuff modifier entries and scenario parts), capped at 256; more than 32 items, or anything not exactly projectable, is unverified. Unverified omits `gear`, never a partial list; `[]` means the tab shows no equipment or apparel.

## Current job and lord reports

`GameJobsReader` mirrors the installed normal inspect caller and report resolution from fields; no provider, generic inspect, job setup or future job queue is executed. `job` and `lordReport` are separate bounded strings, not a combined inspect dump. Both retain unverified Mono/UI status.

- **Independent gates.** Own-pawn admission already proves player faction. Normal mental state blocks lord summary and ordinary job text; `alwaysShowReport` bypasses mental state for job only. ## Things and observed resources

`GameThingsProducer` serves `things.list` and `resources` through the same scheduler, target gate, witnessed raw lister traversal and immutable snapshot validation. Source/host checks and net472 compilation are not normal-UI or Mono proof.

- **Type boundary.** Exact `Thing`, `ThingWithComps`, `Pawn`, `Building`, `Building_Storage`, `Building_Door`, `Building_Bed`, `Building_WorkTable`, `Building_ResearchBench`, `Building_TurretGun`, `Plant` and `Apparel` only. Specialized/custom classes are not implicitly admitted by inheritance. Each definition must be an exact `ThingDef` with matching `thingClass`. Unsupported types are outside this audited eligible projection, not evidence of no objects/resources of those types.
- **Fields.** Bridge-owned `t_` reference, localized normal label (pawn short identity), direct map x/z and positive `stackUnits`. Pawn names reuse the identity mirror after non-player concealment admission; comp-bearing things reuse the gear label mirror, including component/provider/patch checks. Exact plain `Thing` supports only no-stuff/no-HP-extra labels. An admitted visible thing whose label cannot be mirrored makes the whole query unavailable, never a shorter successful list. No generic inspect string, container contents, future state or arbitrary comp getter is evaluated.
- **Complete consistent basis.** Every raw candidate, including excluded ones, is charged and witnessed before filtering. `ConsistentSnapshotSource` latches any structure, eligibility-revision or field-admission change from build start through publication; it cannot reset witnesses and publish an old decision vector. Stack counts join the plain-field witnesses. A fog/position/stack/concealment change therefore restarts the whole build (at most twice), or expires a retained cursor. Pages preserve historical DTO values and revalidate the complete vector; no partial scan totals or raw lister indices/counts escape.
- **Resource kinds.** Only that same eligible vector contributes. Exact `ThingDef.CountAsResource` is mirrored as its `resourceReadoutPriority != Uncounted` field comparison, with a patch check; contributors must also be `ThingCategory.Item`. Groups use definition reference identity and its bounded localized public label, never runtime class or localized-label equality. Loose and non-fresh direct stacks count; held/minified inner stacks never do. Every response says `eligible_observed_direct_spawned_stack_units`, not resource-bar or whole-colony totals. ResourceCounter, freshness getters, haul destinations and cached counts are never read or refreshed.
- **Bounds and gaps.** At most 2,048 raw candidates/witnesses, 2 MiB retained bytes, 256 resource kinds, shared per-update candidate/nested/time budgets and ordinary read deadlines. The raw-source cap is checked before filtering or traversal; a larger map list refuses both routes, even with few returned eligible rows. An isolated fixture has demonstrated this refusal, so useful whole-map results on sources over the cap remain a baseline blocker requiring explicit bounded-query/index design, not a larger budget or partial-count fallback. Larger/churning sources or any incomplete projection return uniform failure, not exact lower bounds. Resource results are all-or-nothing and unpaged; things use the existing five-second reusable query-bound cursors. Strict consistency can reduce live availability, and unknown label transforms can refuse both routes even for a non-resource row. Full-profile paused/live usefulness, public labels/counts and hidden-density timing remain real-game checks.

### Larger-map limitation

The current `things.list` and `resources` implementation cannot provide useful whole-map results when the raw source exceeds its existing cap. This is a baseline gap, not an empty result or evidence that no eligible resources exist. It exposes no source count or scan progress in the refusal.

Frozen eligible DTOs do not prove that earlier excluded decisions remain valid. The installed spatial cell lists are mutable, not immutable eligible snapshots or eligibility revisions; partitioning a whole-map query still needs interval validation and multi-cell deduplication. No larger scan or narrower cell-query replacement is enabled. The synchronous all-decision comparison also remains an unproven scheduling cost below the cap. Host controls reject unsafe witness shortcuts; they do not establish useful bounded completion. Independent verification may continue, but cannot turn this limitation into a whole-map or scheduling acceptance pass.
