# Main-thread reads and transition invalidation

`mod/Bridge/ReadDispatcher.cs` is BCL-only scheduling/identity infrastructure; `ModBootstrap.cs` supplies the installed Verse/Harmony adapter. A bounded named developer-safety sampler, private [epochs](observation-epochs.md), shared [producer scheduling](#shared-producer-scheduling) and [snapshot store](#eligible-snapshot-store) guard source-audited baseline, event and screenshot producers. Authenticated [health/capabilities](bootstrap-commands.md) report minimal readiness and registered routes, not proven full-profile availability. Ordinary reads may fail `observation_refused`, `not_ready`, `stale_scope` or `unavailable`, never fabricate empty/healthy data. [Host regressions](../tests/coverage/observation-adversarial.md) do not establish Mono/game acceptance.

## Dispatch boundary

Transport admits only strict, typed read intents to the process-owned queue (16 maximum); forbidden/unknown methods and wrong-session scopes fail before dispatch. Health/capabilities also use this queue, but return only bootstrap primitives without requiring ordinary observation readiness; transition invalidation/deadlines can still reject them. Workers never receive game objects. Each pending read retains its absolute socket/request deadline and cancellation token. Disconnect/watchdog closure cancels its completion; completed/cancelled/expired reads cannot be readmitted or executed. Shutdown cancels queued completions, not only queue membership.

The first audited game-thread callback establishes the owning thread. Pumping from another thread fails before invoking the sampling adapter. Each complete derived Root_Entry/Root_Play.Update finalizer gives developer-safety/identity sampling its own fixed cooperative **2 ms** allowance, then shares the original cooperative **2 ms** producer slice across at most **4** dequeued requests and active work. Root.OnGUI boundaries sample only, without granting another request quota. A nonblocking transition-gate acquisition refuses instead of waiting for a worker. Deadline/cancellation is checked before execution and completion. Remaining queued reads retain their original deadlines; they do not become unbounded per-frame work. Primitive operations, RNG and runtime/GC pauses cannot be preempted by a managed stopwatch; these are cooperative checks plus finite operation counts, not a hard real-time guarantee. Later collection/capture producers must charge work inside traversal and recheck before release.

## Shared producer scheduling

`mod/Bridge/ProducerScheduler.cs` is the one owner for ordinary reads after they leave the queue. The installed adapter attempts to register summary, pawn list/detail, things/resources, UI, events and screenshot producers at dispatcher construction. Failed binding keeps the affected routes unverified; only trusted adapter code can add one per ordinary method (never auth/health/capabilities, never client data).

- **Bounded ownership.** At most **4** active reads per session and **1** snapshot build; extra work gets `busy`. Transition workers reject active work immediately (`not_ready`) and mark it revoked; partial state is discarded on the game thread at the next sample. Disconnect, cancellation and deadline expiry drop work without completion.
- **Independent boundary sampling.** Each safety/readiness boundary sample has its own fixed 2-ms cooperative allowance, independent of producer/event/capture debits. Only the finite audited sampling closure runs there, never producers or extra request dispatch. Producer work retains its original shared 2-ms allowance. Missing/failed/overdue samples still revoke authorization, active work and retained snapshots/cursors. This explicit budget divergence prevents producer overshoot from skipping safety sampling; it does not exempt retained data from revocation or guarantee cursor availability.
- **One shared allowance per Update.** The 2 ms slice, **128** candidates and **1,024** nested fields are shared by every producer step in that update, not reset per request or map. Steps run round-robin from a rotating start, each with a fair share of remaining candidates. GUI boundaries revalidate active work but never step it.
- **Whole-read caps.** **16,384** candidates, **65,536** nested fields, encoded bytes per read (262,144, or 2,097,152 for a snapshot build) and **2,097,152** active bytes session-wide. Exceeding a cap fails uniformly (`unavailable`, or `busy` for shared memory) and discards every partial DTO; no counts or causes reach the wire.
- **Overdue not-ready samples are no source evidence.** A sample that exhausts its own allowance while reporting not-ready refuses reads and revokes retained data/active work but never invents root/game replacement; a genuine not-ready with budget intact still clears identity.
- **Final admission.** A completed continuation is revalidated (developer refusal first, then readiness, epochs, exact start scope and request scope), re-audits whole-result eligibility in the releasing update, then hands primitives to transport inside `ObservationEpochs.Release` under the read fence. A completion that finds no time left is released next update without re-stepping.

Leases are per update: every Update/GUI bracket revokes the previous one. A multi-update continuation therefore needs fresh authorization each update plus its own whole-vector eligibility proof (snapshot task); the scheduler never relabels an old lease.

The adapter checks **AnyEventNowOrWaiting**, the actual Current.Root reference, the root's audited `destroyed` field, initialized uiRoot and transition revision before obtaining Game.Maps. Menu requires Root_Entry/Entry in the active Entry scene; play requires Root_Play/Playing in the active Play scene and a non-null Game. MapInitializing, loading, invalid/destroyed roots and callbacks spanning a transition supply no maps. No loading collection is enumerated, counted, copied or version-tested by the tracker. Known transition callbacks touch only BCL invalidation state, including when invoked by the loading worker.

**An Update return is not end-of-render.** Installed Root_Play.Update calls base.Update, then advances UpdatePlay. Dispatch now follows the complete derived update instead of the base postfix; GUI/rendering comes later. The existing wire phase tag `root_update_postfix` names this post-update sample, not a literal base Harmony postfix. No sample/frame integer here establishes screenshot completion, uninterrupted interval safety, an atomic simulation snapshot or normal-player map eligibility. Update/GUI and finite developer/window/scale mutation brackets irreversibly revoke prior leases; see [boundary audit](observation-epochs.md).

## Audited edges

Postfix polling alone misses a setter changing away and back, a map removed/re-added between frames, a queued long event cleared or completed during Update, and scene teardown before the next root is sampled. The adapter installs exact declared-method signatures, not PatchAll or arbitrary runtime routing:

| Source surface | Invalidation boundary |
| --- | --- |
| Current.Game setter | Every assignment involving a non-null Game, including same-reference writes; proven null-to-null menu no-op excluded |
| Current.ProgramState setter | Every attempted assignment, even same value |
| Current.Notify_LoadedSceneChanged, Root.Start, GenScene.GoToMainMenu | Scene/root initialization and return-to-menu disposal |
| Game.InitNewGame, LoadGame, FinalizeInit, Dispose, World setter | Same-Game reinitialization/world replacement/disposal |
| Game.AddMap, DeinitAndRemoveMap, Map.Dispose | Map membership/lifetime edges, including failed attempts |
| MemoryUtility.ClearAllMapsAndWorld | In-place map/world teardown and raw Maps.Clear |
| All three QueueLongEvent overloads, ClearQueuedEvents | Queue/clear edges, including events invisible by postfix time |

Each entered prefix increments a private revision, marks an active bracket and rejects all pending work with `not_ready`; each finalizer balances its entered bracket and invalidates requests admitted while it was active. Nested/worker brackets refuse main-thread sampling until all finish. They never hold a monitor across the original game operation. A short read-side gate serializes sampling against these observers. Reentrant changes during a sample also discard its scope.

Installed `UIRoot_Entry.DoMainMenu` assigns `Current.Game = null` every GUI pass. Invalidating on these empty-to-empty writes permanently starves queued menu commands and rotates menu identities. The Game setter prefix therefore compares only its exact injected static backing reference and incoming value, without getters, object inspection or collections, and excludes only null-to-null. All assignments involving a non-null Game still enter the normal bracket. Its distinct finalizer state records whether the prefix ran: Harmony classifies reference-argument prefixes as skippable, so a skipped prefix conservatively creates and balances an invalidation rather than assuming a no-op. Finalizer retry remains idempotent.

Installed Harmony source treats the other void prefixes with only `out __state` as non-skipping observers even when an earlier prefix returns false. State initializes false; an earlier prefix exception cannot cause an unmatched finalizer decrement. The finalizer clears its ref-state before balancing, so Harmony retry after a later finalizer throws cannot decrement twice. The void finalizer neither suppresses nor replaces original exceptions/results. Prefix priority is First, postfix/finalizer priority Last; other mods can still interfere. All target signatures and IL bodies were independently resolved from installed metadata. This is not proof that Unity Mono detours every full-profile call: tiny setters can be inlined, and incompatible patches can bypass expected behavior.

## Bounded reference generations

No numeric game/map ID, overloaded Equals or Unity equality establishes identity. The main-thread tracker retains one root, one Game, one Maps list, one List enumerator witness and fixed arrays of at most **128 map references/IDs**. Unknown/null/duplicate/over-ceiling populations fail closed and drop retained references. Map IDs are random and allocated on demand, only for maps passing the audited [map access gate](visibility-audit.md#target-gates), which is rechecked on every resolution; an unknown, removed or inaccessible map ID returns `unavailable`, while a root/game mismatch returns `stale_scope`. Eligible-only pawn/thing references (at most 8,192, oldest evicted) are dropped with every rotation. At most 128 map slots and 8,128 duplicate-reference comparisons are checked per sample, with time checks between slots. No unbounded dictionary/history of removed objects exists.

Any observed edge, root/Game/list replacement or Maps mutation conservatively rotates the entire root/game/map scope and invalidates pending work. This deliberately expires unaffected maps too. Removed/re-added references never regain old identities. Loss of readiness clears all retained scopes, so same-reference return after loading gets fresh identities.

Game exposes mutable List<Map>. Between safe samples, a retained enumerator's single MoveNext checks List's private version, then the tracker replaces the witness. Installed Mono source checks version even for empty/exhausted lists; Remove/Add, Clear/re-add and even assigning the same reference through the indexer therefore invalidate identical final membership without patching shared generic List code or reflecting private list fields. This one version probe runs only after readiness gates, never during loading. Reflection/unsafe writes bypassing List's version, version wrap after billions of mutations and concurrent writers outside audited transition/loading brackets are not supported synchronization guarantees. Later adapters must remain inside the same dispatcher and validate visibility/readiness/release safety independently.

## Eligible snapshot store

`mod/Observation/SnapshotStore.cs` holds frozen eligible page data for list routes. No route uses it yet.

- **Frozen rows.** A finished build becomes a snapshot of at most 2,048 projected rows and 2 MiB. Rows are copied in and copied out, never rewritten; later value changes need a fresh query.
- **Retention.** At most four snapshots, oldest evicted, five seconds from creation. A snapshot is kept only after a passing whole-vector check in the same update.
- **Cursors.** Each page boundary gets one random `q_` cursor the first time it is needed, reused by every later poll (at most 2,048 per snapshot). A cursor is bound to exact scope (including map), method and limit. Unknown, evicted, timed-out and wrongly bound cursors all look the same (`cursor_expired`). Pages carry no total, offset or raw index; `complete` means end of the frozen snapshot.
- **Whole-vector check before every page.** Every member reruns its audited target gate, one nested field charged per member first. Any ineligible member, a throwing gate or a structural source change since the build started expires the whole snapshot and its cursors, without naming the row.
- **Interval protection.** The check spans updates only while an audited eligibility revision supplied by the source stays unchanged from first to last member. Without that revision the whole check must fit one update; a pass that yields restarts from the first member next update. A revision change mid-pass also restarts.
- **Expiry.** Any generation rotation (root, game, maps, transitions, not-ready samples) and any sample whose observation authorization is refused expire every snapshot, cursor and in-flight check.

Without an eligibility revision, a snapshot larger than one update's nested allowance (1,024) can never pass. List adapters must supply audited structure and eligibility witnesses.

## Verification scope

Asset-free tests compile the actual dispatcher/tracker and exercise reference replacement, same-reference edge/list returns, empty-list mutation, map removal/re-add, duplicate/null/over-ceiling populations, loading and nested-worker refusal, queue invalidation/count/time limits, cancellation/deadlines and unavailable observations. Game-assignment regressions cover repeated menu null writes, null/non-null and same-reference assignments/returns, skipped-prefix invalidation and finalizer retries; the no-op regression fails under the original unconditional invalidation. They use synthetic game objects and host sockets, not real Verse reads.

Configured net472 compilation checks the real adapter, signatures available to the compiler and proprietary output boundary. Installed game/Mono/Harmony source and metadata support the transition/version model. A separate attempt to run installed Harmony's dummy-method detours under host .NET 10 failed in Harmony/MonoMod initialization with MethodAccessException; it provides no detour pass and is not a Unity Mono failure result. A later authorized isolated full-solo-profile Unity Mono run reached the normal menu with the packaged product: exact-session discovery, queued health and capabilities succeeded, including twelve explicit repeated command samples. The original unconditional Game-setter invalidation failed the menu regression; excluding only proven null-to-null writes restored service in the real game. This proves the exercised startup/menu path, not every detour. Pause/load/root changes, same-reference game/map transitions, quitting delivery and native cancellation stress remain NOT RUN. See [runtime evidence limits](../tests/coverage/session-adversarial.md#isolated-menu-runtime-proof).
